The two audit regressions failed against the previous implementation and passed after the fixes. The first holds a GET in flight, observes a newer HTTP command response plus stale receipt/socket revisions, and completes the older GET afterward: neither snapshot callback publishes stale data, the highest known revision remains monotonic, and the pending reconciliation loop fetches/publishes the newer state. Only an up-to-date HTTP snapshot can confirm completion. Historical command views remain unapplied and global revision gaps remain valid.

The second sets a realtime frame ceiling below a valid HTTP snapshot's size: realtime parsing still rejects that frame, while authenticated HTTP reconciliation delivers the snapshot and continues after the socket policy failure. Shared structural validation has no frame-size ceiling. HTTP JSON instead uses a separately configurable transport limit, `maxHttpResponseBytes` (default 2,097,152 bytes), enforced before parsing against Content-Length and actual streamed bytes.
